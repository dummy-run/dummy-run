# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- The `dummyrun-target-size` fix example sets a minimum width and height of 24 CSS pixels. The `dummyrun a11y --keyboard` help says it reports each control that works only by mouse.
- Severity and confidence come from rules over recorded facts, never from the model. The persona's `finish` tool no longer asks for a severity. The engine sets it from the symptom's impact class and whether the finding is on a journey, and a report sets each failing axe rule's severity the same way, from the impact, the WCAG level, the pages affected and whether a persona's journey crossed the page. Only a critical impact makes a blocker. A reviewer can still change a severity.
- `confidence` on a sweep's failing elements now means how often findings with the same inputs have turned out to be right: `high`, `medium`, `low` or `unknown`, looked up in a table that ships with the engine, instead of `high` or `single` from the engine count alone. Every failing element has one, with or without `--engines`. An engine with no measured record of its own is `unknown`, never `high`.

### Added
- Each `dummyrun a11y` result whose page loaded records `state`: a SHA-256 hash of the page's structure and text, read just before the rules run, and how many elements it covers. It covers each element's tag, role and ARIA, its states and the page's text. It leaves out styles, classes, ids, link addresses and form values. Equal hashes mean the page had the same structure and text, so you can tell a page that changed from a sweep that did.
- `dummyrun a11y --content` checks the words and images a page's authors wrote. It reports vague link names such as "read more", links named with a web address of more than 30 characters, links that open a new tab without saying so, and document links whose name doesn't give the right file type. It reports alt text that is a file name, starts "image of" or runs past 150 characters. It also reports bold text that looks like a heading, text in capitals and underlined text that isn't a link. The results are advice, as `dummyrun-content-<check>`, and never fail the sweep. The phrase checks run only on pages in English or with no language set. `--all` includes it.
- `dummyrun a11y --lighthouse` runs Lighthouse's accessibility and best-practice audits once for each URL, in the Chrome the sweep already has open. Lighthouse's accessibility audits are axe-core rules, so where it fails an element our axe failed, the node gets `lighthouse: true` and never counts as another engine. Its other accessibility failures are candidates, and its best-practice failures are advice, as `dummyrun-lighthouse-<audit>`. Each URL records the two scores. Lighthouse runs only in Chrome and isn't in the container image. `--all` includes it, and without it each page says why it wasn't audited.
- `dummyrun a11y --layout` now measures layout from the rectangles the browser lays out and what it paints on top at a point, so a box that only reaches into another box no longer counts. Clipped text covers all text, not only controls, and counts only text that is partly inside the box. Text a carousel hides, and teasers shortened on purpose, are left out. An overlap needs one control on top of the other's text. Reflow leaves out data tables, images, maps, video and toolbars, which WCAG 1.4.10 lets scroll. It also leaves out a skip link parked past the left edge, which can't make the page scroll. Target size adds the exception for controls the page leaves at the browser's own size. A new rule, `dummyrun-focus-obscured` (WCAG 2.4.11), reports a control that is entirely hidden, such as behind a sticky header, once it has focus. An image, video or canvas hides it only where its pixels are solid.
- A test benchmark plants known barriers in clean pages. It reports how many of them the sweep finds for each check. It also runs 150 real elements from the AccessGuru dataset (MIT) one by one. See [Check the sweep against known problems](docs/ENGINE.md#check-the-sweep-against-known-problems).
- Every persona finding records its `inputs` in the run record (schema version 2): the kind of evidence (`measurement`, `ax-fact`, `engine-rule` or `model-only`; `task-verdict` is reserved for checks that try a task), the engines that agree, the check ID, whether it is on a journey and, with repeated runs, in how many runs it reproduced. Earlier records, which have no `inputs`, still validate and a report reads each of their findings as the persona's own report. A reader built from an earlier copy of the schema rejects a record that has `inputs`, so update readers before the engine. Each rule in a sweep says what kind of `evidence` it is. Reports show a confidence badge and a "How sure" line on every finding and failing rule, with one sentence saying what it rests on, and the report JSON carries the inputs. The Grafana exporter reads the new field.
- `dummyrun calibrate` rebuilds the confidence table from labelled findings and writes a calibration report: each band's observed accuracy, each bucket's stated accuracy against the labels it rated, and whether the bands discriminate. The shipped table is built from `internal/confidence/labels/`, and a test keeps the two in step.
- `dummyrun a11y --keyboard` now tries up to 5 controls on each page by mouse and by keyboard. A control that works when clicked but not from the keyboard is reported as `dummyrun-mouse-only` (WCAG 2.1.1). Each verdict is computed: the success test, such as `aria-expanded` becoming true, must be false on a fresh load and true after the click. It also checks that a skip link moves focus to its target, as `dummyrun-skip-link-no-focus` (WCAG 2.4.1). Links to other pages, `javascript:` links and submit buttons are never picked, nor anything holding one, and a signed-in sweep tries nothing. A mouse-only control is the first `task-verdict` finding, so the report rates it a blocker.
- In Chrome, roles, names and states now come from Chrome's own accessibility tree. That covers the control list, the outline and the `a11y` tool. The engine reads the tree with `Accessibility.getFullAXTree` over the Chrome DevTools Protocol. It reaches the protocol through chromedriver's `goog:cdp` passthrough, since WebDriver BiDi has no command for it. So an icon button named by CSS content gets its real name, where it showed `(no name)` before. Each look in Chrome whose tree was read records `names_from: chrome`. Firefox keeps the engine's own name script. So does anything Chrome's tree leaves out, such as a control in a frame.
- `dummyrun a11y --html` checks each page's HTML with the Nu HTML Checker (vnu). It checks the HTML as the server sent it and the page as the browser built it, in one run. It keeps only errors that change what assistive technology gets, such as duplicate IDs, a control inside another or a bad ARIA value. The results are advice and never fail the sweep. `--all` includes it. The container image now includes the Nu HTML Checker 26.10.12 on a Java runtime cut down with jlink, which takes the image from 1.22 GB to 1.37 GB.
- `dummyrun a11y --journeys` finds the journeys each page offers and tries each by mouse and by keyboard: search, the menu, sign-up, the basket, booking and the contact form. It finds them on the page, without a model, and lists any journeys the site's technologies suggest that the page has no way into. Its tab sends only GET and HEAD requests. It skips links that add to the basket, pages robots.txt disallows with `--respect-robots`, redirects included, and signed-in sweeps. Each journey has a success test that must be false at the start and true after the action, and nothing is ever submitted. A journey that works by mouse but not by keyboard is a violation, `dummyrun-journey-keyboard` (WCAG 2.1.1).
- A run reads what the site is built with from its first page and records it in `target.tech`, with the marker that showed each one. The categories suggest journeys worth a persona's time, in `target.journeys`: a shop suggests basket and checkout, a search form suggests search. The engine's own fingerprints cover about 40 platforms. Set `DUMMYRUN_WEBAPPANALYZER` to your copy of webappanalyzer to use its 6,000 or so as well. webappanalyzer is GPL-3.0, so it isn't bundled. The new `target` fields are optional, so earlier records still validate. A copy of the run record schema from before this change rejects records that have them, so update any copy you keep, such as one a pipeline validates against.
- `dummyrun a11y --links` checks the links on each page with lychee, each link once across the sweep. The sweep reports a link that answers with an error status or can't be reached as `dummyrun-broken-link` advice. The advice gives the URL, and the status code when there is one. Some sites turn automated checkers away with 401, 403, 429 or 999. Those links, ones that don't answer in time and skipped ones aren't broken: they count in `links_refused`, `links_timed_out` and `links_checked`. Behind preview access, links on the swept sites are checked from the browser, so lychee never gets your credentials. Links to `localhost` and private addresses are skipped, unless every URL you sweep is on one, and so are links robots.txt disallows with `--respect-robots`. `--all` includes it, and the container image now includes lychee 0.24.2.
- `dummyrun a11y --keyboard` presses Tab through each page. It reports focus you cannot see, which it checks by comparing pictures with and without focus. It also reports focus that lands on a hidden or off-screen element, focus that gets stuck and a skip link that goes nowhere. A walk that stops early says so with `keyboard_partial`. A dialog with one control is never called a trap. The walk starts from the top of the page, even when it opened at a `#fragment`. A page with nothing to Tab to counts as fully walked, and a trap test that cannot finish shows as an error. Rules `dummyrun-focus-not-visible`, `dummyrun-focus-hidden`, `dummyrun-keyboard-trap` and `dummyrun-skip-link-broken`.
- `dummyrun a11y --markup` adds two markup checks: `dummyrun-label-in-name` (a control whose visible words are missing from its accessible name) and `dummyrun-autocomplete-missing` (a field for your own email, phone, first name, last name or postcode with no purpose-specific autocomplete value).
- `dummyrun a11y --all` turns on every check flag in one sweep: `--keyboard`, `--markup`, `--consent`, `--engines`, `--image-contrast`, `--html`, `--lighthouse`, `--journeys`, `--links`, `--layout`, `--content` and `--plain-language`. Lighthouse runs only in Chrome, and a signed-in sweep tries no journeys. Each check flag's help now starts "also", so the flags read the same way.
- Reports say how to fix each rule from Dummy Run's own checks. A failed rule gets a summary and the steps to take. It also says who usually makes the change: content, design or development. Most rules come with an example and the W3C or GOV.UK guidance behind the advice. The JSON report carries the advice as `fix`. A Dummy Run rule with no help link no longer gets a Deque link.
- `dummyrun a11y --image-contrast` measures the text axe-core leaves for review, usually text on a photo or gradient. It hides the text, takes a picture of what is behind it and compares the text colour with every pixel. Text whose median pixel contrast is too low is reported as `dummyrun-contrast-over-image` (WCAG 1.4.3). `image_contrast_unmeasured` counts the elements it couldn't measure.
- `dummyrun a11y --plain-language` reads each page's main content with Vale. It reports Flesch reading ease and grade, sentences over 25 words, words the GOV.UK style guide asks you to avoid and Latin abbreviations. This advice does not fail the sweep. Text the page's CSS hides is left out. The container image now includes Vale 3.24.0.
- `dummyrun a11y --consent` answers a cookie banner by rejecting, with DuckDuckGo autoconsent, after the rule engines have seen it and before the layout checks. A banner with an accept button and no reject button is reported as advice, `dummyrun-consent-no-reject`. Each result records the banner's buttons, whether autoconsent opted out and whether the banner has gone. A banner that turns up while autoconsent is still looking, in about the first three seconds, is answered too. A page where autoconsent can't start fails.
- A persona whose modality is `screen-reader-view`, such as `screen-reader-user`, now gets what a screen reader says on each look: the current page read from the top, one phrase per line, from guidepup's virtual screen reader. It's computed from the page's accessibility semantics as they are at that look, so it changes when the page does.
- `dummyrun a11y --engines` runs IBM Equal Access, HTML_CodeSniffer, Siteimprove Alfa and QualWeb inside the page beside axe-core. QualWeb brings its ACT rules and its WCAG techniques. It matches their results by element and WCAG criterion. Each axe violation node says which engines agree and how confident the result is. A failure two other engines agree on is a violation (`dummyrun-engines-<criterion>`). One that only one engine reports goes to `candidates`, which never fail the sweep. The report's `engines` field lists their versions, and `engines_ran` names the ones that ran. A contrast failure from any of these engines on text no one can see, such as a button label pushed off the page or clipped away, is left out. Text that spills out of its element but stays on the page, or that a scrolling box holds out of view, is still checked. So is fixed or absolutely placed text outside a parent that does not contain it. [Tools we build on](docs/TOOLS.md) credits each engine with its licence.

### Changed
- Unless you set `--viewport` or `--text-scale`, `dummyrun a11y --layout` now adds the 320 px window and a run at 200 percent text, the two settings WCAG 1.4.10 and 1.4.4 name.

### Fixed
- In Chrome, pages fetched ahead of a click skipped the request interception. A page asks for these with speculation rules, and Chrome can add rules of its own. The requests Chrome made for them carried no run headers and skipped the request policy. Chrome now starts with preloading off.
- The screen reader stops reading after eight seconds, even when the page stops answering. A persona that gets no screenshots now hears the page even when it may not click. What it says is scanned as visible text, and each phrase is cut at 300 Unicode code points.
- The keyboard and mouse comparison leaves out text fields, comboboxes and tabs reached by the arrow keys, which it reported as working only by mouse.
- Each rule engine has its own time limit, so one that hangs is an error for that engine alone. Alfa's findings on an attribute, such as a `lang` value that isn't a language, are kept, and every engine finding's selector names one element.
- The plain language check reads the first `main` element that shows, counting text directly inside one with `display: contents`. Failing that, it reads the first one that is displayed, then the first one, then the body when a page has none. Its findings name that element when a page has more than one `main`. Its readability messages match their thresholds, and it removes its temporary rules when the sweep ends.
- Reports show how to act on Dummy Run's own advice, such as plain language, and link a fix that has no help page instead of saying none was recorded. Long examples wrap.
- The terminal summary lists the plain language, HTML, Lighthouse and cookie banner checks that couldn't run.

## [0.1.4] - 2026-10-24

### Security
- Built with Go 1.27.3 and golang.org/x/net 0.60.0. Go 1.27.3 distrusts the compromised eMudhra intermediate certificates in crypto/x509 (GO-2026-6809). Go 1.27.2 fixes HTTP/1 and HTTP/2 flaws in net/http (GO-2026-6610, GO-2026-6611, GO-2026-6612, GO-2026-6613, GO-2026-6617) and a MIME header limit bypass in net/textproto and mime/multipart (GO-2026-6608). golang.org/x/net 0.60.0 fixes the same HTTP/2 flaws in golang.org/x/net/http2. `dummyrun-otel` gets the same update.

## [0.1.3] - 2026-10-21

### Changed
- A page's own images, stylesheets, fonts, scripts, media and fetch calls may come from any public host by GET or HEAD. A persona now sees a site with its CDN the way a visitor does. Page loads still stay on `allowed_hosts`, and that includes frames and pop-ups. Every write to another host is still blocked. A read-only target still blocks every write to its own hosts. A subresource is refused when its host is, or resolves to, an internal address such as loopback, private, link-local, carrier-grade NAT or another special-use range. That holds even for a local target, unless the host is in `allowed_hosts`. The run's trace headers go only to the target's own origins. A page's own scripts can now send data they can read to a public host in a GET address, as they can for any visitor. Allowed subresources are no longer noted as blocked on the step (code: `internal/policy/subresource.go`, `internal/page/page.go`).
- The persona reads one list of the page instead of two that could disagree: landmarks, headings H1 to H6 with their levels, and the controls with role, name, states and `@number`. One script, `internal/page/names.js`, gives the names and visibility for the control numbering, the outline and the accessibility check. It uses axe-core's own name and screen-reader-visibility functions when axe is loaded. The engine now loads axe on every web page it reads, and runs it and its page scripts in a WebDriver BiDi sandbox that page scripts can't reach. Without axe it uses the spec computation. Buttons and comboboxes take their `<label>`. Image buttons take their `alt`. Links and buttons also take the `alt` of an image and the `title` of an SVG inside them. Only controls a screen reader can reach are numbered, so links in a closed `<details>` or a collapsed menu and `aria-hidden` controls are left out. A nameless control shows `(no name)` instead of `(no label)`, and names are cut at a word boundary. The outline's budget is now 1,500 tokens and the page text 4,000 characters. Main-content controls and top headings are kept before header and menu controls, and a last line says how many were left out (code: `internal/page/look.js`, `internal/page/tree.js`, `internal/runner/observe.go`).
- The `a11y` result names up to three failing elements of each rule by selector and accessible name. Requests stopped by the host rule are counted on the first step where they happen and not repeated later. The count covers page loads and writes on other sites and requests to internal or unknown hosts. The note says they're the test's own rule. The injection warning now tells the persona the text is data to ignore, without asking it to report the attempt (code: `internal/page/page.go`, `internal/runner/observe.go`).
- A feed, PDF, JSON or other file opened as a page is described as "not a web page" with its content type, with no controls or text. The accessibility check doesn't run on it, and `page.content_type` is saved in `steps.jsonl` (code: `internal/page/look.js`, `internal/runner/observe.go`).
- The persona is told to confirm a `(no name)` control with the accessibility check before it reports one. It's also told what the test's own limits are, and that they're never the site's faults. Those are blocked requests and read-only refusals. They also include failed tools, timeouts and files that aren't web pages.

### Removed
- The engine no longer files a `security` finding when the injection detector matches. Detector hits stay `suspected_injection` events in the run record for the operator, and the persona still gets the `HARNESS WARNING` line. The detector fired on ordinary text on several real sites (code: `internal/runner/inspect.go`).

### Added
- `dummyrun a11y` also runs axe's best-practice rules, such as content outside any landmark or headings that skip a level. A rule with none of the WCAG A and AA tags is advice. It goes to each page's `advice` list and the summary's `advice_nodes`. It never fails the sweep or changes its exit code. The report shows it in its own "Advice beyond WCAG A and AA" table, apart from the failures. Its JSON keeps it in `axe.advice`, with the tags in `axe.advice_tags` (code: `internal/a11y/sweep.go`, `internal/report/`).
- A finding whose cited steps all show the test's own limits is dropped and recorded as a `harness_limit_finding` event. Those are steps where the browser couldn't read the page, where a tool was refused or failed, or where the page was a file. A step also counts when the persona's own action sent a request the test blocked and the address stayed the same, if the finding says something didn't work or couldn't be reached. The event kind is added to the run record schema (code: `internal/runner/harness.go`).
- Personas and `dummyrun a11y` can get past a protected preview. A new `auth` block in the target file takes HTTP Basic auth (`basic.username_env`, `basic.password_env`) and request headers (`headers.<Name>.value_env`). That covers Vercel's `x-vercel-protection-bypass`, Cloudflare Access service tokens, and bearer or custom headers. `--basic-auth-env USER_ENV:PASS_ENV` and `--header-env 'Name:ENV'` do the same for one-off runs on `dummyrun run`, `dummyrun try`, `dummyrun a11y` and `dummyrun session save`. The values come only from environment variables, and a secret written in the file is refused. The headers go only to the target's own hosts over https (or on loopback), never to another host, including through a redirect. The engine also answers Basic auth challenges as a fallback. The read-only policy is unchanged. The run record has an optional `preview_access` block that names the methods and the header names. A reader built from an earlier copy of the schema rejects a record that has it. Nothing secret reaches the record, the log, screenshots, telemetry, errors or reports (code: `internal/access/`, `internal/policy/auth.go`).

### Fixed
- A persona visiting the Get started page on dummyrun.dev no longer reports that page content tries to instruct an AI persona. The page's sample run quotes engine output about injection, and the script that plays it faded each unplayed line out at zero opacity, which the injection scan reads as concealed text even inside `pre` and `code`. The terminal now covers unplayed lines with a CSS mask, so the text stays visible to the scan as quoted output. The engine rule is unchanged: concealed text inside code is still flagged. A browser test loads the real stylesheet and script (code: `site/assets/js/site.js`, `site/assets/css/site.css` and `internal/runner/site_terminal_test.go`).

## [0.1.2] - 2026-10-21

### Added
- `dummyrun browsers install [chrome|firefox|all]` downloads the pinned Chrome for Testing and its matching chromedriver into your user cache (`os.UserCacheDir()/dummyrun/browsers/<version>`), checks each file against a hash (SHA-256) that ships with the program. The engine finds them there when `DUMMYRUN_CHROME` and `DUMMYRUN_CHROMEDRIVER` are unset. `dummyrun browsers list` shows what is installed. Firefox uses the copy on your machine, or the pinned release on Linux. The pins live in `internal/browsers/versions.json`, and a test checks them against `.github/workflows/engine.yml` and `docker/Dockerfile` (code: `internal/browsers`).
- `dummyrun try URL` plays the first-time visitor from the persona library against one page for about 15 steps, read-only, and prints the findings and where the run is saved.
- `dummyrun run` and `dummyrun try` choose a provider when you leave out `--provider`. They try `DUMMYRUN_AZURE_ENDPOINT` first. Then come `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` and Ollama on `OLLAMA_HOST` or `localhost:11434`.
- The first line of output names the provider and model, and `--model` is optional for these, except with Azure, where the deployment name is yours. The defaults are in `internal/provider/detect.go`, with a generated table in `docs/PROVIDERS.md`.
- A scenario can ask for a minimum number of steps with a `Min steps: 8` line. The engine answers a `finish` that comes sooner with a note to carry on, and the run continues. It lets the `finish` through when the verdict is `blocked`, when the step budget, the token budget or the persona's patience forced it. After three refusals it lets the next one through too. `dummyrun run --scenario-file FILE` plays a scenario file that is not in the cast (code: `internal/runner/patience.go`, `internal/cast/cast.go`, `cmd/dummyrun/main.go`).
- A "Docs move with the code" check on every pull request. A behaviour change in `cmd/`, `internal/`, `casts/library/`, `schema/`, `integrations/`, `docker/`, `.goreleaser.yaml` or `site/layouts/` fails unless the same pull request changes the docs and adds a line under Unreleased here. Tests, `testdata/` and `internal/tools/` are ignored. The message names the pages that path usually affects. The `no-docs-needed` label with a `Docs: not needed because ...` line in the description is the way out. `CONTRIBUTING.md` and the pull request template describe it (code: `.github/workflows/docs-guard.yml` and `.github/scripts/docs-guard.sh`).

### Changed
- The website reads like a person wrote it. Every page a visitor reads is rewritten in a warmer voice with varied sentences, and none of them carries Sources sections, evidence tags or lists of what is planned. The style guide describes the new voice. `bin/check-prose` now only warns about long or comma-heavy sentences, fails on machine-copy words and em dashes, and has its own tests in `bin/check-prose-test`.
- `dummyrun report` has a designed HTML report. It has a cover with the logo and the client. The cover also has the target, the dates, a plain summary and a bar of problems by severity. The summary page has key-number cards and a plain statement of how many problems are still unfound. Findings are cards with a severity band and badge, grouped by severity under a contents list. The axe sweep is a table, and baseline status has clear labels. The brand typefaces are embedded, with a light theme and a dark one on screen only. Print has page breaks, a running title and page numbers. The Markdown format has the same structure in headings and tables. The example report and its pictures are rebuilt, and `docs/REPORT.md` has a tour (code: `internal/report/templates/` and `internal/report/assets/`).
- `--provider` no longer defaults to `azure`. With `DUMMYRUN_AZURE_ENDPOINT` set, Azure is still the first choice, so existing commands keep working.
- The installation guide, the Get started page, the README and the engine guide now start from the release download, then `dummyrun browsers install`, one API key and `dummyrun try`. Azure is one option among several. The "pre-release" wording is gone now that 0.1.1 is out, and `SECURITY.md` supports the newest release.
- The animated flow on the how-it-works page breaks out of the text column to the width of the header. Gaps, cards and mini-stages are larger. It follows 3, 2 or 1 columns by width. Each card shows its finished content until its turn, so no card looks empty. Reduced motion and no JavaScript still show every finished state (code: `site/assets/css/site.css`).

## [0.1.0] - 2026-10-20

### Changed
- The terminal on the Get started page now plays one real run. You see a persona run against dummyrun.dev, the steps it took, and the report command with its result. The commands type out, the output appears in chunks, and a button pauses it. With reduced motion, the whole transcript shows at once. The raw capture and its run ID are in `site/data/start-session.json`, and `bin/check-start-session` checks that each output line is in the capture, is a shortened captured line or is an ellipsis.
- The home page hero shows a real step and a real finding from the recorded run, in place of the made-up Inkwell phone.
- The website speaks to the reader as "you" on pages written for them. The style guide has the rule. `bin/check-prose` warns about "their" after "a QA lead", "teams" and the other listed audience phrases (code: `bin/check-prose` and `docs/STYLE.md`).

### Fixed
- The layout checks no longer report the content of a closed `<details>` as on the page, and no longer report two links that wrap in the same paragraph as overlapping when their lines do not meet (code: `internal/page/layout.js`).
- The website holds up with a larger text size. At 320 pixels wide with a 32 pixel default font, twice the normal size, parts of the site broke. The header and home page buttons overlapped. The sign-up and scan forms, the persona library and the footer ran off the edge or scrolled the page sideways. The header links now fold behind a Menu button that says whether it is open, or show as a wrapped list without JavaScript. Grids let text shrink. Buttons and chips wrap their own text, and so do long words and addresses. The human check and code blocks stay inside their box (code: `site/assets/css/site.css`, `site/assets/js/site.js` and `site/layouts/_partials/header.html`). The site workflow runs `dummyrun a11y --text-scale 100,200 --layout` on every page at 320 pixels wide, so the faults cannot return (code: `.github/workflows/site.yml`).
- The injection scan skips eligible visible code and quoted text on pages that explain prompt injection. The Model providers page on dummyrun.dev mentions `finish` in code, and the scan does not file a security finding for it. It still scans concealed text and stronger visible matches. A lone visible "system prompt" or "call `finish`" becomes a `low confidence` event and does not create a finding.
- The OpenAI-compatible provider now sends an empty string as the text of a turn that only calls tools. Before, it left the field out, and a local Ollama server answered "invalid message content type" (code: `internal/provider/openai_compat.go`).
- The Grafana exporter retries annotations on HTTP 429 (#34). Annotation lookup also retries on 5xx. Annotation creation does not retry on 5xx. Grafana may have stored the annotation. The exporter waits for `Retry-After`, spaces its calls and spends at most ten minutes on annotations in one export. If an annotation still fails, the exporter still sends and flushes all the telemetry. It then lists the failed annotations and exits with code 3. Code 3 means some annotations failed after any selected telemetry arrived. `--signals traces,metrics,logs,annotations` chooses what to send, so a re-export can send only what is missing. The dogfood workflow treats code 3 as a warning.
- Browsers are no longer left running after runs and tests (#49). The engine starts the driver and the browser in their own process group. It closes the session and stops the group. It then waits for the exit and removes the temporary profile. This holds after an error or a panic. It also holds after a timeout, Ctrl-C and SIGTERM. A watchdog stops the browser if the engine is killed. Every test closes its browser, and CI fails when one is left behind. `docs/ENGINE.md` covers cleanup and troubleshooting.
