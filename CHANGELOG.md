# Changelog

All notable changes are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- The terminal on the Get started page now plays one real run. You see a persona run against dummyrun.dev, the steps it took, and the report command with its result. The commands type out, the output appears in chunks, and a button pauses it. With reduced motion, the whole transcript shows at once. The raw capture and its run ID are in `site/data/start-session.json`, and `bin/check-start-session` checks that each output line is in the capture, is a shortened captured line or is an ellipsis.
- The home page hero shows a real step and a real finding from the recorded run, in place of the made-up Inkwell phone.
- The website speaks to the reader as "you" on pages written for them. The style guide has the rule. `bin/check-prose` warns about "their" after "a QA lead", "teams" and the other listed audience phrases (code: `bin/check-prose` and `docs/STYLE.md`).

### Fixed
- The injection scan no longer flags pages that explain prompt injection. It skips visible code and quote text. The Model providers page on dummyrun.dev mentions `finish` in code and files no security finding now. Hidden or off-screen text and the attributes people use to hide text are still scanned. A lone visible "system prompt" or "call `finish`" becomes a `low confidence` event and files no finding.
- The OpenAI-compatible provider now sends an empty string as the text of a turn that only calls tools. Before, it left the field out, and a local Ollama server answered "invalid message content type" (code: `internal/provider/openai_compat.go`).
- The Grafana exporter retries annotations on HTTP 429 (#34). Annotation lookup also retries on 5xx. Annotation creation does not retry on 5xx. Grafana may have stored the annotation. The exporter waits for `Retry-After`, spaces its calls and spends at most ten minutes on annotations in one export. If an annotation still fails, the exporter still sends and flushes all the telemetry. It then lists the failed annotations and exits with code 3. Code 3 means some annotations failed after any selected telemetry arrived. `--signals traces,metrics,logs,annotations` chooses what to send, so a re-export can send only what is missing. The dogfood workflow treats code 3 as a warning.
- Browsers are no longer left running after runs and tests (#49). The engine starts the driver and the browser in their own process group. It closes the session and stops the group. It then waits for the exit and removes the temporary profile. This holds after an error or a panic. It also holds after a timeout, Ctrl-C and SIGTERM. A watchdog stops the browser if the engine is killed. Every test closes its browser, and CI fails when one is left behind. `docs/ENGINE.md` covers cleanup and troubleshooting.

### Added
- The README, the How it works page and the Telemetry page answer four questions that the dogfood personas raised. Dummy Run does not replace a scripted regression suite. Screenshots and page text go to the model provider you choose (inferred). Telemetry carries no screenshots, and it carries step URLs and finding titles that can quote the page (code: `integrations/grafana/exporter/internal/telemetry/plan.go`). It goes only to your OpenTelemetry backend, so its residency is wherever that backend is. Findings become tickets by hand or from the run record JSON (code: `internal/record/record.go`). The architecture and How it works pages list the model providers and link the provider table.
- Observations are kept apart from findings. The `finish` tool now takes `findings` for problems only (code: `internal/runner/tools.go`) (something wrong, missing or confusing) and `observations` for what worked and neutral notes. The system prompt explains the difference with an example of each. Run record schema version 2 gains an optional `observations` list of `text` and `steps` (code: `internal/record/record.go`). Observations do not count as findings in coverage, in reports or in the findings metric, and the exporter does not send them. A report lists them separately. A finding that a model still marks `class: observation` is moved to the observations. `dummyrun report` lists them in a What worked section, labelled as not checked by a person (code: `internal/report/build.go`).
- The site header has a Free scan button that links to `/scan/`, and Get started moves into the nav (code: `site/layouts/_partials/header.html`). The home hero has the buttons Get a free scan and Run it yourself (code: `site/layouts/home.html`). The home page has a Free scan section with the three steps and the waitlist form (code: `site/layouts/home.html` and `site/layouts/_partials/scan-steps.html`). `/scan/` is a landing page with an example report, the waitlist form at the top and at the end, and a link to the scanner page (code: `site/layouts/scan.html`). The persona library, how it works and get started pages each carry a Try a free scan note (code: `site/layouts/_shortcodes/try-scan.html`).
- `--identify` and `--respect-robots` for `dummyrun run` and `dummyrun a11y`, and `identify` and `respect_robots` in the target file. `--identify` ends the browser's user agent with `DummyRun/<version> (+https://dummyrun.dev/scanner/)` on Chrome and Firefox (code: `internal/telemetry/telemetry.go`). `--respect-robots` fetches the target's robots.txt before the run starts, and `a11y` fetches it once for each origin. It honours the rules for `DummyRun` and `*`. A disallowed path is blocked like an off-origin request and noted on the step (code: `internal/policy/policy.go`). A disallowed start page stops the run before the browser starts. The run record has the outcome `blocked`. The command exits with status 3 (code: `cmd/dummyrun/main.go`). `a11y` skips disallowed pages (code: `internal/a11y/sweep.go`). The run record gains optional `target.identify`, `target.respect_robots` and `outcome_reason`, in schema version 2. A reader with an earlier copy of the schema rejects a record that uses them (code: `schema/run-record.schema.json`).
- Inkwell seeds a draft that the author Sam owns and that waits for a verdict. Sam can try the self-review rule on it without submitting a draft first, and the approval works only when the `perm-owner-self-review` switch is on (code: the seed data in `examples/inkwell/server.go`).
- Inkwell is a made-up publishing app in `examples/inkwell`. It has five roles and seeded test accounts. A `-defects` manifest plants up to thirty-six faults, and a hidden prompt-injection test is available. `-test-login` signs a run in with a cookie route. `casts/inkwell` adds an author and a reviewer persona. `docs/INKWELL.md` covers it (code: `examples/inkwell/`, `casts/inkwell/` and `docs/INKWELL.md`).
- The website has a link-preview card for each main page. The program `internal/tools/socialcards` draws them (code: `internal/tools/socialcards/main.go`). Each page has Open Graph and Twitter tags, which are the tags that chat and social sites read to build a preview. The home page also has JSON-LD, which is a block of data that describes the software to search engines (code: `site/layouts/_partials/head.html`). The start page opens with a terminal that plays real command output (code: `site/assets/js/site.js`). Code blocks get a copy button when the browser allows clipboard access, except diagram sources and record output (code: `site/assets/js/site.js`). The home page has a one-line list of facts and a star link (code: `site/layouts/home.html`).
- `dummyrun mcp` serves Dummy Run to coding agents over the Model Context Protocol. It has four tools: `list_personas`, `a11y_sweep`, `run_persona` and `get_run`. It tests only localhost, private hosts and sites given with `--allow-origin`. Each call and each session has a cap. The persona library is now built into the program. `docs/MCP.md` has the setup for Claude Code, Cursor, VS Code and Codex.
- Sign in for authenticated apps. A target file can declare a `signin` block with a login form and credentials for each role, read from environment variables. The engine signs in before the persona starts, so the model never sees the password. The persona or the scenario picks the role. The read-only policy lets exactly the declared sign-in request through while the engine signs in and then returns to strict. A declared sign-out path is blocked for the whole run. The run record gains an optional `signin` block. `dummyrun session save` signs in once and writes a Playwright-compatible session file, and `--session FILE` on `dummyrun run` and `dummyrun a11y` loads it. `docs/ENGINE.md` and `SECURITY.md` cover it.
- `dummyrun report --format badge` writes a small SVG badge for a README, such as "4 open · 17 Oct 2026". `--format shields` writes the matching shields.io endpoint JSON. The count is confirmed findings, or findings no one has reviewed with `--include pending`. The colour follows the highest open severity. The badge never uses a word that reads as a verdict. `docs/BADGES.md` says what it claims and shows how to publish it from GitHub Actions.
- `dummyrun report` turns run records and `dummyrun a11y` results into an audit report. The default is one self-contained HTML file that prints to PDF. `--format` also writes Markdown, JSON, SARIF and JUnit. The report has a plain-language summary and the scope and method. It also has the coverage numbers, an axe section and a statement of what the report is not. Findings are grouped by fingerprint and sorted by severity. Only confirmed findings appear unless `--include pending` is given, and those are marked not reviewed. `--baseline` marks each finding new or still present and lists the fixed ones. `schema/report.schema.json` describes the JSON, `docs/REPORT.md` explains the report and `examples/report/` holds an example.
- `docs/THREAT-MODEL.md` lists the assets, the trust boundaries and the threats from a hostile page, with the code that stops each and the gaps. The code is in `internal/inject`, `internal/runner` and `internal/policy`. It is linked from `SECURITY.md` and sits on the website.
- Defences against prompt injection. The model sees page text between markers that label it as untrusted data, and the system prompt says page text never changes the task (code: `internal/inject/inject.go` and `internal/runner/observe.go`). The address and title of the page sit inside the markers too. Text the browser does not render is collected but not sent (code: `internal/page/look.js`). Text that looks like an instruction to the persona adds a warning to the step, a `suspected_injection` event in the run record and a `security` finding that the engine files itself (code: `internal/runner/inspect.go`). A finding that cites no step in the run is dropped and recorded as an `uncited_finding` event. A record keeps at most 25 events of each kind.
- Run record `events`, the finding kind `security` and the outcome `provider_filtered`, all optional additions to schema version 2. A reader with an earlier copy of the schema rejects a record that uses them (code: `schema/run-record.schema.json`). `dummyrun-otel` loads a record that has them and ignores `events` (code: `integrations/grafana/exporter/internal/record/record.go`).
- When a model provider's content filter refuses a call, the run ends as `provider_filtered` with a plain message (code: `internal/provider/filter.go`). A reply that holds a `refusal` counts as a refusal too. This holds for every provider, including Azure.
- A canary page of injection attempts, `internal/runner/testdata/canary.html`, and browser tests that play a scripted model against it.
- The pricing page has four plan cards, a tax line, an open-source band and a short FAQ. The terms, refund and privacy pages share one legal layout. It has a summary box, a table of contents, a date and a contact block.
- A page at `/audit/` for requesting an audit. Its form stays hidden behind `audit_form_enabled` until the Worker is live. Until then the page shows an email fallback (code: `site/layouts/audit.html`).
- `dummyrun review` is the human review stage. It shows the pending findings one at a time with their steps and screenshot paths. A person confirms, rejects, edits or skips each one. `--list`, `--confirm` and `--reject --reason` do the same without a terminal. A problem seen in several runs is judged once and the verdict reaches every pending finding with that fingerprint. A decision rewrites the record through a temporary file and a rename, and adds a line to `review-log.jsonl`. Only confirmed findings count in a report unless you ask otherwise (code: `internal/coverage/report.go`). Two reviewers in one folder take turns (code: `internal/review/lock_unix.go`). `docs/ENGINE.md` has a Review section.
- Run record schema version 2 gains the optional finding fields `reviewer`, `reviewed_at` and `reason`. The examples in `examples/runs/` carry them on reviewed findings, and `dummyrun-otel` accepts them (code: `internal/record/record.go` and `integrations/grafana/exporter/internal/record/record.go`).
- `gpt-5-4-mini-global` is in the price table, from the Azure retail prices API, so runs on that deployment get a `cost_usd`.
- A Watch a run page on the website. It replays one real run of the dummyrun.dev cast. Each step shows the screenshot, the action, the outline the persona read and the findings that cite it. The data is in `site/data/replay.json`, from run `2026-10-19-priya-qa-lead-does-it-replace-my-suite-31099a2c8c853e8f`.
- `docs/ETHICS.md`, on the website as Ethics and limits. It says what a persona can and cannot tell you, how the screen-reader persona works and what goes to the model provider.
- The persona library page on the website shows a card for each persona with filters by need, what the persona does differently, what it looks for and the command to run it. It is built from the files in `casts/library`. Each persona gains five front matter keys that the page reads.
- `dummyrun doctor` lists the browsers and profile directories that an earlier run left behind. `--stop` stops them and removes the directories.
- `dummyrun coverage` counts what a set of runs covers. It reports the problems found and a Chao2 lower bound on the problems still unfound, always as "at least" with its form named. It also reports sample coverage and the expected new problems per extra run. Route and persona-dimension coverage, a stratified stopping rule and scoring bands complete the report. It refuses to pool runs from different builds. `docs/COVERAGE.md` says what each number means and when to trust it.
- Run record schema version 2. Each finding has a `route` and a `locus`. It also has a `symptom` from a closed list and a `fingerprint` that the engine computes. Steps have a `route`. The persona has `dimensions` and the scenario has `goal_met`. The record has `repeat_index`, `seed`, a required `batch` and `target.route_universe`. `usage.cost_usd` comes from the price table in `internal/price`, with a source and date for each model, and is null for a model that is not in it. Version 1 records stay readable by `dummyrun coverage` and `dummyrun-otel`. The version 1 schema is kept as `schema/run-record.v1.schema.json`. The exporter gains the attributes listed in `docs/TELEMETRY.md`, such as `dummyrun.finding.fingerprint`.
- `dummyrun run` takes `--seed`, `--repeat-index` and `--universe`. The `finish` tool asks for `goal_met` and for a `symptom` on each finding. A finding may name the control it is about. A URL target without a commit is identified by a hash of its home page.
- A weekly workflow plays the `casts/dummyrun-dev` cast against dummyrun.dev, sends the run records to Grafana Cloud and keeps them as an artifact (code: `.github/workflows/dogfood.yml`). It fails when a scenario does not run, when a record is not completed or when the export fails.
- `dummyrun run` plays one persona through one scenario in Chrome or Firefox over WebDriver BiDi, with thirteen tools and a step and token budget. A read-only mode blocks every request that could change data. The run record matches `schema/run-record.schema.json`. `docs/ENGINE.md` covers it.
- Each observation names the element that has focus and lists an accessibility outline. A persona can set `zoom` from 100 to 500 percent and `tools-allowed` or `tools-denied`, and a scenario can set its own `Device:` and `Zoom:`. The run record gains `persona.zoom`.
- `dummyrun a11y` takes `--rebase`, `--viewport`, `--scheme` and `--headful`. `dummyrun audit a11y` is the same command.
- `casts/library` holds ten generic personas, from a screen-reader user to the viewer, editor and admin trio. `docs/PERSONAS.md` says how to copy one. `keyboard-only-user` cannot click, `screen-reader-user` is not sent screenshots and `low-vision-zoom` runs at 200 percent.
- `dummyrun-otel` sends run records to Grafana as OpenTelemetry traces, metrics and logs, with annotations. Four dashboards, a local stack and four alert rules go with it. `docs/integrations/grafana.md` is the guide.
- `docs/CLI.md` is written from the commands' help text, and the capability table in `docs/PROVIDERS.md` is written from the code. CI fails when either is out of date, and shell blocks marked `<!-- doctest -->` run in CI against a local build.
- The website at dummyrun.dev, built with Hugo from this repository and checked for accessibility on every change.
- Model providers beyond Azure: any OpenAI-compatible service or local server, Anthropic, Gemini (Vertex AI and the Developer API) and Amazon Bedrock. `docs/PROVIDERS.md` covers each one.
- `--reasoning-effort` and `--openai-api responses` for OpenAI-style models, and `cached_input_tokens` in the run record's usage.
- `dummyrun a11y` sweeps pages with axe-core for WCAG 2.2 A and AA on Chrome and Firefox, with no model calls. The site's accessibility check now uses it in place of pa11y-ci, which removes the extract-zip alerts.
