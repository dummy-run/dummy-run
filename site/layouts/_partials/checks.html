• Getting round by keyboard

    We press Tab through each page. You find out if the focus can’t be seen or disappears, if the skip link goes nowhere, or if a visitor gets stuck.

  • Forms that fill themselves in

    Fields for a name, email, phone number or postcode should tell the browser what they’re for, so it can fill them in. We also check each button’s spoken name matches the words on it.

  • Zoom and bigger text

    Unless you choose your own window or text size, we look at each page in a narrow 320 px window and with the text at twice its size. We look for sideways scrolling, words that overlap or get cut off, and buttons too small to tap.

  • Text people can read

    Where text is too faint, we suggest the nearest colour that is clear enough and keeps your colour’s hue. Where text sits on a photo, we measure its contrast against the picture behind it.

  • Plain English

    We read your main text for long sentences, hard words and Latin phrases, and give it a reading-ease score. With the content checks on, we also flag alt text that is a file name, bold text standing in for a heading and, on pages in English, links called “read more”.

  • Was it the same page?

    Each page we can read gets a fingerprint of its elements and text, so when two sweeps disagree you can see whether the page’s content changed in between.

  • When things go wrong

    We load each page again as if your API were down. Nothing but reads reaches your server, and we check whether an alert or live region tells screen reader users that something failed.

  • What changed since last time

    Keep a picture of each page between sweeps and we count the pixels that changed, with a picture of where, so you can spot a deploy that moved things. Cover a clock or an advert so it doesn’t count.

  • The same answer twice

    Pages change from one load to the next. Ask us to test each page a few times and each problem from the page checks says how many of the runs it turned up in. We don’t judge which problems come and go: you compare the counts. Journeys, links and the other checks that run once for each page are tried in the first run only.

  • Cookie banners

    We answer your cookie banner by saying no to everything optional, and tell you if it gives visitors no way to refuse.

  • More than one opinion

    Other accessibility checkers read each page beside axe-core. What axe finds, or two of the others agree on, is a finding. What only one of the others spots goes in the sweep’s results as a candidate for you to look at, up to 200 for each page.

  • What a screen reader says

    The screen-reader persona works from what a screen reader would read out, in order, so you can see where it gets lost.
