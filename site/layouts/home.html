What it checks

Alongside the personas, an accessibility sweep reads every page. Each problem comes with its evidence, so you can see it for yourself.

  • {{ partial "icons/icon.html" (dict "name" "movement") }}

    Keyboard

    Focus you can’t see, skip links that go nowhere and places a visitor gets stuck.

  • {{ partial "icons/icon.html" (dict "name" "zoom") }}

    Zoom and bigger text

    A 320 px window with text at twice its size. Sideways scrolling, clipped words, tiny buttons.

  • {{ partial "icons/icon.html" (dict "name" "vision") }}

    Contrast

    Faint text, with the nearest colour that is clear enough and keeps your hue.

  • {{ partial "icons/icon.html" (dict "name" "language") }}

    Plain English

    Long sentences, hard words and Latin phrases, with a reading-ease score.

  • {{ partial "icons/icon.html" (dict "name" "clipboard") }}

    Forms

    Fields the browser can fill in, and buttons whose spoken name matches their words.

  • {{ partial "icons/icon.html" (dict "name" "speaker") }}

    Screen readers

    A persona that works only from what a screen reader would read out, in order.

Straight answers

Does it replace our scripted tests?
No, keep them. A script checks the steps you wrote down. A persona wanders off and tries the things nobody thought to script. How they work together
Can a persona replace testing with disabled people?
No. A persona simulates a barrier so you catch likely problems early and cheaply. It can’t tell you how a disabled person would actually get on. Only testing with disabled people can. Ethics and limits
Do screenshots leave our network?
Only to the model provider you pick, and never from the screen-reader persona. Runs stay in your own folder or bucket, and the telemetry you send to Grafana carries no screenshots. What goes where
Which browsers does it drive?
Chrome and Firefox, in desktop, tablet or phone-sized windows, with page zoom up to 500 percent and system text size up to 300 percent. Browsers and devices
